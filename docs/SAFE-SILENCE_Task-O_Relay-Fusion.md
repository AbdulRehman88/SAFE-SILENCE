# Task O — Criticality-Preserving Relay Fusion

Task O implements the bounded relay operator frozen in the Task C system model. It consumes only
packets already generated by Task J. Silence produces no relay item, and no hidden network state,
future observation, receiver-side truth, or evaluation-only field is available to fusion.

## Proposed operator

For each item, the relay computes the configured evidence-per-payload-byte score from critical
evidence, environmental uncertainty, deadline urgency, and residual magnitude. Critical evidence
receives the locked dominant weight so that a lower-ranked noncritical heartbeat cannot displace
the highest-ranked alert. Ties are resolved by sensing timestamp, source identifier, and item
identifier.

The merge is

\[
F_K(A,B)=\operatorname{TopK}_K(A\cup B), \qquad K=4.
\]

Item identifiers are content-checked and deduplicated. Under the deterministic total order this
operator is commutative, associative, and idempotent. Every batch is audited under original,
reversed, rotated, item-ID-sorted, and differently grouped input orders.

## Relay summary and accounting

The proposed summary stores the retained item identifiers and exact sensing/source provenance,
critical-evidence maximum, environmental-uncertainty maximum, deadline-urgency maximum, earliest
and newest sensing times, merged/retained/dropped counts, relay sequence, input-set digest, CRC,
and explicit encoded bytes. Membership logs record every retained or capacity-dropped item and its
reason. Expiry and quality-rejection counters are present but remain zero because those upstream
checks are not simulated in this component task.

The structural relay batch contains eight sequential generated packets from one immutable Task J
window and retains four. This fixed 2:1 stress construction is declared before Task O evaluation;
it is not fitted to development or external results. A final partial batch is retained rather than
discarded.

## References and endpoints

`no_relay_fusion` forwards every packet independently. `mean_relay_fusion` emits a single mean
summary and intentionally carries neither individual items nor critical maxima. The latter tests
whether rare evidence is diluted. All three policies are compared using critical-item retention,
highest-ranked-critical preservation, critical-batch detection, extrema/provenance preservation,
order-audit failures, and encoded wire bytes.

Only the proposed method stores row-level membership and fused summaries. Reference policies are
kept in the metric registry, avoiding duplicated observations.

## Claim boundary

Task O establishes a deterministic, bounded, order-robust fusion mechanism and measures its
component-level evidence preservation and byte accounting. It does not recover packets lost before
the relay, model Bloom/sketch collisions (exact provenance is used), replay acoustic delivery,
measure modem energy, or establish end-to-end network superiority. Task P evaluates tail-risk reduction per modeled joule.
Tasks Q and R evaluate integrated delivery and receiver/recovery outcomes; actual resource
consumption is reported alongside outcome differences.
